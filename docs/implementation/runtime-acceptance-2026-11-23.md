# 第一阶段日用边界复查：2026-11-23

当前整体 **PARTIAL**，仍按 P0＋P1 首个可日用版本推进。本次补充剪贴板容量、终端交接与退出收尾，未把局部回归当成完整日用验收。

## 剪贴板接纳与采集

曾用合成数据复现两个缺陷：固定条目占用预算时，新条目先挤掉旧历史、随后自身也被删除，却返回成功；数据库逐出失败时留下超限的半笔写入。失败测量保留于 `.local/clipboard-capacity-red.log`。

现在插入与逐出在同一 SQLite 事务中执行。先识别重复正文，再计算固定条目预算；无法容纳时返回明确拒收原因，保留原记录。成功接纳的新 ID 排除在逐出候选之外，时间回拨也不会让刚接受的条目被误删。数据库失败整笔回滚。固定条目不自动删除；正文容量与 SQLite 文件大小是两个口径。

生产 ClipboardMonitor 通过惰性来源接口先取元数据，再按类型、来源提示和变化计数检查，最后才读正文。新增纯内存来源验证敏感标记与排除在正文读取前生效、读前／读后变化不会落盘、暂停与会话恢复不补采，以及 stop 后排队轮询不读正文。容量或单条超限通过类型化结果传到设置／剪贴板页面，下一次成功记录清除旧提示。

这12项定向测试使用合成内容和真实 SQLite，不启用个人剪贴板采集。真实各来源应用的标记行为仍待验收，前台应用仍只是来源提示。

## 终端交接

此前等待 NSWorkspace 打开回调时仍显示可取消，实际上无法撤回已经提交的系统请求；退出还可能无限等回调。现在提交前仍可取消，提交后进入 `handoffPending`，显示明确说明并移除虚假取消入口。

TerminalHandoffAdapter 默认等待确认3秒、可配置预算硬上限5秒。明确确认只表示打开请求被接受，不表示命令成功；明确拒绝记失败。无确认则记 `interrupted / terminal.handoffUnknown`，保留仍可能被系统打开的脚本，提示先检查 Terminal；不自动重发，迟到或重复回调不能改写终态。重启同样恢复 unknown，重复恢复同 ID 不生成第二项任务。

10项合成回调／Store／intent恢复测试通过，包含排队时退出不提交、静默回调下退出有界、不可撤回状态、迟到回调、拒绝清理与确认恢复。没有打开 Terminal GUI；工具此前明确禁止访问 Terminal，实际终端执行继续保持 **PARTIAL**。

## 实际原生操作

环境：macOS27.2／arm64，本地 ad-hoc Debug、KeyDockSafeSmoke隔离模式。真实剪贴板、选区采集、凭据与权限请求关闭。

- 最新中文剪贴板设置说明实际可见，包含单条1 MiB、32 MiB正文及固定项满额规则，页面没有裁切；录制开关保持禁用。
- 从菜单打开启动台，搜索并执行本工程合成 `/bin/sleep 30`。先确认子进程仍在运行且属于当前 App 的独立进程组，再通过 CmdQ 正常退出；App与该子进程均消失，durable回执为 cancelled／exit143，执行约17秒，早于自然结束。证据在 `.local/p1-native-quit-smoke.json`。
- CUA注入的 alt+space 未产生可观察启动台切换。尚不能区分注入限制与注册行为；没有将该尝试计为快捷键通过，仍需真实按键、冲突和IME验证。
- 复查发现悬停选择触发自动滚动，静止鼠标可能连续命中新行。已把滚动请求与选择状态分离：悬停只更新选择，键盘移动／结果回退才请求滚动；窗口会话定向回归覆盖此合同。最新构建实际复验：初始选中第一项且列表保持顶部，六次Down准确到第七项并滚入可见范围，搜索焦点保留。工作区同时显示重启后的sleep为已取消／exit143，复制和AI解释禁用，明确说明正文不保留。证据在 `.local/p1-launcher-hover-native.json`。
