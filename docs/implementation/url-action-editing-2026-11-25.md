# URL动作编辑隔离复查

2026-11-25，alpha.8候选在界面语义修补基础上增加此修复。完整产品仍PARTIAL，发行证据另行登记。

## 问题与实现

此前Use和Launcher深链接设置运行选择ID，URL表单却把同一ID用于保存；只使用A后填写新B就可能覆盖A。表单字段为View局部状态，导航／提示条重建后还可能出现空字段和旧运行ID组合。

现在WorkspaceSession独立持有编辑ID、名称和模板。Use／深链接只选择运行目标，只有Edit加载编辑身份；新建与成功保存整体重置草稿。切换页面或语言保留完整编辑草稿。已删除编辑目标拒绝保存，不隐式重建。配置写入失败复用原事务回滚，并把语义错误显示到当前工作区；成功清除旧错误。新建上限100项有明确提示，到达上限仍可编辑既有动作。

## 原生观察

先Use已有合成Native URL，再填写Synthetic URL B并保存：两行同时保留，新建表单清空，运行选择仍为原动作。随后编辑原动作名称，Use B、离开工具页再返回，原动作编辑ID／名称／模板仍保留，运行目标保持B。切换English后同一草稿仍显示Editing URL action和原字段；英文浅色820×664实际截图检查了列表、编辑标题、表单与按钮，未见该子集明显截断。

把模板暂改为javascript scheme后保存，工作区显示明确验证提示，名称／模板仍保留、旧动作未改。恢复合法模板再次保存后，仅原动作改名，B未变，错误消失，表单回到New URL action。全程没有点击Open URL，没有打开浏览器、请求API或运行命令。没有通过UI删除记录；合成B保留在隔离Preview。语言和外观均已恢复跟随系统。

删除目标／文件写入故障／100项上限由合成单元测试注入验证，没有将它们报告为真实UI故障注入通过。中文标签与英文切换实际AX已观察，URL表单完整深浅色／VoiceOver／键盘矩阵仍待验收。
