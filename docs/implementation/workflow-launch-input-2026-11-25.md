# 工作流输入入口与原生复查

2026-11-25，继续`fix/ui-semantics-and-text-sync`；主Agent独占修改／构建／设备，子Agent只读完整范围复查及代码评审。当前正式安装和公开Release仍为alpha.7，alpha.8没有因本轮局部通过而放行。

## 实际问题与修补

旧快捷入口固定调用`runWorkflow(...,input:"")`，绕过工作台输入：文本变换可空结果成功，AI步骤可能将空文本送入模型。改为先编译校验，再按真实数据依赖分类；需要初始文本时只打开指定工作流的独立输入页。固定命令／固定文字仍直接运行，手动输入步骤不重复问两次。

独立输入稿与现有编辑器分离，呈现UUID拒绝旧按钮／取消后的迟到操作。定义变更须重载审阅，删除拒绝，重载保留文本；超预算输入整次拒收并禁用运行，后续合法编辑解除。主窗口的运行／停止解析在其模态sheet持有键盘时停用，防止操作被遮住的编辑稿。

进一步核对App发现专用工作流快捷键仍先走通用Launcher的`captureTarget`。已改为上下文无关的专用入口：取消旧捕获／generation，按真实catalog与`.shortcut`授权执行，失效或无关ID只显示工作区错误。通用Launcher为其他动作的原有预捕获行为没有整体重写；它捕获的选区不会被工作流准备自动当作初始输入。合同见[技术文档](../technical/workflow-launch-input.md)。

## 原生子集

- 在隔离Preview保存纯trim流程`Synthetic Input Review B`，另建不同ID的未保存稿`Synthetic unsaved editor A`，保留输入`Keep this editor input`。
- 启动台选择B后，560×440输入页显示B及正确步骤，输入初始为空、Run停用；输入后Run启用。打开File菜单确认主窗口运行与停止停用，⌘Return没有启动A或关闭输入页。
- 取消返回，A的名称／输入仍在。再次从最近入口打开B，确认未复用取消前输入；明确点击运行后显示B的已完成任务，输出为去除首尾空白后的`Synthetic reviewed input`。返回编辑页，A仍未保存且内容保留。
- 英文深色输入页截图检查标题／说明／步骤／输入／按钮，Esc取消成功；返回英文编辑页后A仍保留。最后语言与外观恢复跟随系统。中文浅色及英文深色仅为该尺寸和流程子集，不等于四组合全应用验收。

未启用计划、删除保存数据、使用剪贴板、运行CLI GUI、配置真实API、代授予权限或请求外部模型。Native运行只有本地纯文本变换；真实printf仅在隔离进程测试中执行。定义改变、失效、容量和迟到按钮由单元注入，未宣称原生故障注入通过。v2快捷键派发由helper回归与App静态评审覆盖，物理Carbon按键仍未计PASS。
