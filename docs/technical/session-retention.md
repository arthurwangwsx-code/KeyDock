# P1 会话与元数据保留方案

2026-11-23，待实现方案。当前只有单次输入128 KiB、输出1 MiB限制；会话总量、90天清理与任务清除入口尚未实现。对应iSpec 3.8、4.11，不扩展P2完整RunStore/Activity分析。

| 范围 | 计划默认值 |
|---|---|
| CLI＋AI执行中任务 | 最多8个，包含queued、handoffPending和终态落盘收口 |
| 会话历史／草稿 | 最多200条任务、32份草稿 |
| 会话文本 | 32 MiB UTF-8逻辑预算，计入输入、输出、notice、选区和未审阅提案；不是进程RSS保证 |

| 每份InvocationStore | 已结束记录最多2,000条、4 MiB、90天；进行中intent不逐出 |
| usage文件 | 最多5,000条、16 MiB、90天，单份最多64 KiB |
| 未审阅提案 | 最多10项，关联来源runID |

容量满时先逐出最旧终态，保护执行中、当前窗口草稿和选中结果；无法满足预算则拒绝新任务/输入。启动、每日及保存后维护元数据，按JSON recordedAt计时；只处理专用目录内UUID文件，不跟随符号链接。损坏记录计入容量并报告，不能当零消耗。

任务只有在`taskHandles[id] == nil`后才可删除。AI的UI completed早于usage/回执收口，不能只按状态清理。删除联动处理resultTargets、proposalRequests、latestRunID、latestAutoCopyRunID和来源提案；释放窗口强引用，并拒绝旧UI再次提交已删除草稿。历史清除推进generation，拒绝启动时旧快照迟到插入。Terminal unknown交接脚本可能仍被OS打开，保留独立清理语义。

设置→隐私提供两个独立确认入口：“清除已结束任务与AI草稿”说明丢弃闲置未保存草稿、保留执行中数据；“清除AI用量记录”说明运行请求结束后仍可能产生新记录。不联动删除配置、命令、AIAction、凭据或剪贴板。任一存储失败明确报告部分完成。

必要验证：第9个任务无外部副作用；长期历史总量有界；运行/可见对象保护；90天边界及数量/字节逐出；completed但handle未释放不能删除；清除与恢复交错不复活；存储失败部分完成；重启无正文、无重放。
