# P1 会话与元数据保留

2026-11-23。本轮已实现并通过合成回归；原生清除交互与长期驻留验收仍待完成。对应iSpec 3.8、4.11，不扩展P2完整RunStore/Activity分析、正文持久保存或附件。证据见[本轮复查](../implementation/retention-acceptance-2026-11-23.md)。

| 范围 | 默认值与行为 |
|---|---|
| CLI＋AI执行中任务 | 最多8个，包含queued、handoffPending和终态落盘收口 |
| 会话历史／草稿 | 最多200条任务、32份草稿 |
| 会话文本 | 32 MiB UTF-8逻辑预算，计入输入、输出、notice、选区和未审阅提案；不是进程RSS保证 |
| 单份文本 | 输入保留128 KiB、输出1 MiB；输入超限拒绝，不静默截断 |
| 每份InvocationStore | 已结束记录最多2,000条、4 MiB、90天；进行中intent不逐出 |
| usage文件 | 最多5,000条、16 MiB、90天，单份最多64 KiB |
| AI命令提案 | 待审与正在审阅合计最多10项，关联来源runID |

容量满时先逐出最旧终态，保护执行中、当前窗口草稿和选中结果；无法满足预算则拒绝新任务/输入。启动、每日及保存后维护元数据，按JSON recordedAt计时；只处理专用目录内UUID文件，不跟随符号链接。损坏记录计入容量并报告，不能当零消耗。

任务只有在`taskHandles[id] == nil`后才可删除。AI的UI completed早于usage/回执收口，不能只按状态清理。删除联动处理resultTargets、proposalRequests、latestRunID、latestAutoCopyRunID和来源提案；释放窗口强引用，并拒绝旧UI再次提交已删除草稿。历史清除推进generation，拒绝启动时旧快照迟到插入。Terminal unknown交接脚本可能仍被OS打开，保留独立清理语义。

设置→隐私提供两个独立确认入口：“清除已结束任务与AI草稿”说明丢弃闲置未保存草稿、保留执行中数据；“清除AI用量记录”说明运行请求结束后仍可能产生新记录。不联动删除配置、命令、AIAction、凭据或剪贴板。任一存储失败明确报告部分完成。

合成覆盖：第9个任务无外部副作用；长期历史总量有界；运行/可见对象保护；90天边界及数量/字节逐出；completed但handle未释放不能删除；清除与恢复交错不复活；存储失败部分完成；重启无正文、无重放。

会话为每份草稿预留完整128KiB输入和8KiB提示空间，为执行预留整份输出、输入快照和元数据，并预留一个面板上下文槽位。预算包含会话输入、输出、提示、保留选区及待审/正在审阅的提案源数据；UI/网络缓冲、系统对象和已保存配置不作为RSS承诺。可见草稿的当前运行结果按动态runID保护，不依赖窗口重新赋值。接纳先规划完整逐出集合，拒收时不误删部分历史。被删除文档清正文/目标，旧引用不能读剪贴板或再提交AI。

Core内部live lease保护正在消费的回执，宿主释放后才维护；旧intent重启转interrupted/unknown，首次恢复确认后解除恢复保护。回执在固定目录FD内用openat/renameat/unlinkat操作，路径被移动或替换不能转移写入目标。旧历史最多有界读取16MiB后迁移到4MiB写预算；超窗口或损坏保留原文件并失败。保护证据暂时超预算时不删证据，并拒绝新增调用。

同库复合调用的恢复保护在prune前扩展到其已知父／子／兄弟回执；活动parent关联的已确认child不能先被清理。桌面工作区以最小UUID清单和阶段context保存顺序，新增child必须关联active、类型及索引匹配的parent；历史孤立事实只允许读取。总条数、字节与90天策略不变，运行组合根和GUI逐项汇总仍待接入，不把此存储保护表述为完整工作区执行验收。

两类元数据均在启动、每日和保存/收口后维护。usage损坏/超限普通文件保守保留、占容量并报告，可能暂时超预算或阻止新写入；显式清除可删除。自动过期和显式删除同步使旧缓存失效，已保存但仍在回执收口的用量也按真实删除结果处理，迟到reader不复活数值。未知用量不记零，正文不入元数据。

清除等待期间新编辑的草稿按revision识别并保留；各库失败分组报告并保留未清记录，不能显示全清成功。正文只在有界会话内存中，重启只恢复最小元数据。原生GUI、实机权限、长期驻留与文件系统物理故障仍不由合成测试替代。
