# 工作流快捷入口输入

启动台、直接快捷键及集合中的工作流使用同一`execute`入口。先按现有Compiler预检定义和引用，再判断初始输入是否影响实际行为；不能固定传空字符串替代用户未提供的文本。

## 数据依赖

`WorkflowPlan.requiresInitialInput`不依赖UI或OS，按步骤绑定追踪初始输入：

| 操作 | 初始输入合同 |
|---|---|
| trim／uppercase／lowercase | 传递输入依赖；最终输出仍依赖初始文本时收集输入 |
| AI动作 | 当前步骤消费依赖时收集，即使后续覆盖输出也不能省略 |
| 保存命令 | 只有已保存argv含完整`{{input}}`参数才消费；固定命令输出切断依赖 |
| 手动输入 | 由其原步骤明确询问，输出是独立输入屏障；后续显式workflowInput绑定仍指向真正初始输入 |

固定命令→处理前一步输出，以及固定文字流程保留直接运行；不增加无意义的前置输入。无效previousOutput、失效引用和交互模式限制仍由原Compiler拒绝。

## 独立呈现与执行

需要输入时只路由保存工作流ID，WorkspaceSession创建单个`WorkflowLaunchDraft`和sheet，不修改原工作流编辑稿、输入、页面、保存版本或AI草稿。每次呈现有独立UUID；同一目标重入保留内容，不同目标重入要求先完成或取消；旧按钮不能操作新的呈现。

工作流准备本身没有任务、回执、模型请求、剪贴板或选区读取，也不使用通用Launcher为其他动作预捕获的原选区。专用工作流快捷键直接经统一授权入口派发，跳过Launcher的通用目标捕获；通用Launcher的原有捕获行为并未据此宣称整体改为延迟读取。确认前核对保存定义完整值：删除拒绝，修改要求显式重载审阅，重载保留已输入文本。超过131072 UTF8字节的编辑整次拒收，保持旧内容并禁止运行，新的合法编辑才解除；不截断后执行。

点击运行后仍调用原runWorkflow：引用的命令、AI配置和预算在真实启动时冻结；动态argv审批、父子回执、取消／unknown不重放、任务页进度与原调度合同不变。启动失败保留输入页和明确提示。独立输入sheet不新增全局运行快捷键；主窗口的运行／停止菜单在其模态sheet持有键盘时停用，避免运行被遮住的编辑稿。输入、Tab和按钮仍使用系统交互，真实IME另验收。

普通工作流页仍允许用户主动运行其当前编辑稿和明确输入；调度没有交互输入页，继续使用其原先审阅的定义／固定输入和授权指纹。
