# 产品愿景与定位

KeyDock 是面向 macOS 高频使用者的快捷操作与 AI 工作台：让“找到对象、执行动作、查看结果、继续任务”形成一条键盘优先的路径。首要用户是同时使用多个应用、终端和 AI 工具的开发者，也覆盖翻译、总结、文本处理等日常操作。

用户已确认工程代号 KeyDock；2026-11-22 补充 AI 总结、命令行扩展、使用分析、通用 Agent 和可配置 AI 翻译快捷键，均进入产品方向。首个平台为原生 macOS；跨平台、商标和正式产品名尚未定稿。

## 产品原则

1. 一个入口：搜索框、独立快捷键、选区动作、未来工作流均调用同一命令与工具模型。
2. 快捷动作先可日用：应用、窗口、CLI 和翻译/总结在首个版本形成闭环，不等待完整插件市场。
3. AI 为核心域：简单文本任务直接调用模型；多步骤任务使用 Agent。无模型配置时本地桌面工具仍可用。
4. 上下文可见：用户知道将发送的输入、目标模型和输出去向。保存的动作可以在已配置范围内一键执行，范围扩大时再提示。
5. 执行可理解：有参数、目标、进度、结果、取消与错误。生成命令草稿与执行命令是两步明确动作。
6. 渐进扩展：新功能增加 Provider/Tool/Surface，而不修改整个 App 的中心分支或复制一套 UI。

## 差异化假设

系统和成熟竞品已经有强大的搜索、剪贴板与 AI 能力。KeyDock 的机会是可审阅、可扩展的个人工作台：结构化 CLI 运行、本地优先的数据、开放模型接入、可配置的短动作、以及可追溯的个人工作建议。它是待用户测试的假设，不是现有竞品缺乏这些能力的断言。

## 成功指标

| 指标 | 验证办法 |
|---|---|
| 高频任务完成成本 | 用固定任务集比较原操作路径与 KeyDock 的按键、时间、失败和纠正次数 |
| 日用完整性 | 应用、窗口、CLI、剪贴板、翻译/总结各有可重复成功路径，拒绝权限也有明确退路 |
| 性能 | 按验证方案测热唤起、结果延迟、闲置 CPU 和能耗，不把模型延迟计入本地搜索 |
| AI 有效性 | 合成中英文本、技术命令、长输入集检查忠实度、术语、截断提示与命令可执行性 |
| 可控性 | 能取消、清除个人记录、检查上下文、撤销授权，失败后不重复副作用 |
| 可扩展性 | 加入一个新工具无需修改搜索 UI 或模型适配器，至少用三个异质工具检验接口 |

不以功能数量代替质量。前期不追求 Raycast 扩展兼容、完整宏编辑器、常开屏幕监视或自研通用终端。
